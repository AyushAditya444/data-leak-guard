# Evaluation report

_Generated by `python -m leakguard.evaluation report`. Do not edit by hand._

## What was measured

- Datasets: **test** (1600 messages), **handwritten** (93 messages). All data is synthetic or hand-written; no real person's data is used.
- **Matching rule:** a detection is correct when it has the **same type** as a gold span and **overlaps** it; each gold span and each detection is matched at most once.
- **Coverage:** share of gold characters hidden by *any* detection, whatever its type. This is the leak metric: 100% means nothing of that value reached the LLM.
- **Exact:** share of correct detections whose boundaries match the gold span exactly.
- Thresholds were tuned on the **dev** split only; the numbers below are from data the tuning never saw.
- **Name model:** `xlmr-hrl` = `Davlan/xlm-roberta-base-ner-hrl@253f557`, ONNX int8, 280 MB, 1 CPU thread(s). Chosen on dev: see [ner-comparison.md](ner-comparison.md).

## Methodology notes

- After the final round of dev-set tuning, the test-set errors were inspected once. They revealed one defect class the dev set did not contain: key names with a prefix (`DB_PASSWORD=...`, `db_password: ...`). A dev template with that pattern was added, the detector was fixed against dev, and the report regenerated. Test SECRET recall before this fix was 72.9%; the test set was not used for any other decision.
- UPI recall on the test split is pulled down by one hard template with two unknown UPI handles per message; see *Known-hard formats*.
- Phase 4 extended the dataset (name forms, separate dev/test name pools, capitalised words that are not names). The seeded generator therefore produced new samples, so non-NAME rows moved slightly from the Phase 3 report. The name model, its threshold and int8 mode, and the cue-based fallback for lowercase/all-caps names were all chosen on dev only; no test-set inspection informed any Phase 4 decision.
- The cue phrases of the name fallback (e.g. `mera naam ... hai`, `... bol raha hoon`) were written by the same author as the message templates, so the fallback's test numbers may be optimistic. The hand-written set and the lowercase test template without any cue (`bhaiya ... ko parcel de dena`) are the more independent checks.
- Phase 5 extended the dataset (address styles, places drawn from India Post's PIN directory with dev and test using different districts, invented localities that are not post offices, and address look-alikes such as real PINs used as OTPs or order numbers). `agent_record` grew from 150 to 180 and `hard` from 100 to 170 messages per split so every address style has at least 20 samples. Non-ADDRESS rows therefore moved from the Phase 4 report: UPI, PAN and PHONE recall fell because the larger `hard` category holds more of their known-hard formats (unknown UPI handles, spaced PANs, numbers as words). On dev, adding the address detector changed no other type's recall.
- Every address setting (gap 24, the name model's location tags on, the place stop list) and every address detector fix (locality endings such as Layout/Colony as places, dropping a leading place joined only by ordinary words, absorbing a name that overlaps an address) was chosen from the dev split; see [address-tuning.md](address-tuning.md). No test-set inspection informed any Phase 5 decision.
- The address keyword lists, the generator's address vocabulary and the hand-written addresses were all written by the same author, so address numbers may be optimistic. In particular, the generator's invented localities (in both splits) often end in Layout, Colony or Extn, which the detector recognises as locality endings. Places and PINs in generated addresses come from the same PIN directory the detector uses (snapshot downloaded 2026-10-25), so directory places are found by construction; about a quarter of generated addresses use an invented locality instead.
- `landmark_only` addresses ("near the metro station", no place) are labelled as addresses but are not addresses by the detector's definition, so they are counted as misses on purpose; see *Addresses by style*.
