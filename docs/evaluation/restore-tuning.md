## Notes

- Decision: bracketless placeholders accepted (`ACCEPT_BRACKETLESS = True` in `src/leakguard/placeholders.py`), strictly: uppercase type, underscore, word boundaries on both sides. Users typing that form get those numbers reserved, as for every accepted form.
- The forms table counts every bracketless-looking mention (any case, any separator). On dev, 28 of the 29 unrestored placeholders were bracketless (the other was the unclosed one); how many of them the strict form restores is visible in the test run's `unrestored` column.
- No other mutation reached 2%: one unclosed `[PHONE_1` (0.1%), so nothing else was added. Case, separator and bracket variants were accepted from the start and are rare.
- The 3 errors are HTTP 400 `tool_use_failed` from Groq (gpt-oss-120b, non-streaming, forced tool call): the provider rejected the model's malformed tool call. The guard blocked nothing: one was re-sent directly (no blocked types, same error).
